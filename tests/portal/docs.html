The API

Agents reach sql-warden only through MCP (the Model Context Protocol): there is no REST API. A server serves one profile, chosen when it starts; the tools take only SQL, so an agent can't change what it may read.

Which transport?

MCP runs over two transports, and the CLI skips MCP altogether. This portal uses Streamable HTTP: a web page can't start a process to talk to over stdio.

The HTTP transport is local only for now. It listens only on 127.0.0.1, refuses to start on any other address, and rejects requests whose Host or Origin isn't loopback, so another web page can't reach it through DNS rebinding. It has no authentication yet, which is why it stays on loopback.

In production (Phase 9 of the plan), HTTP opens up together with authentication. Each client sends a token, and the server works out the identity and the profile from it, so a client never names its own profile. stdio needs no token: whoever launches the process has already chosen its profile.

A session

Every client does the same three steps, which the portal's Console panel shows:

  1. initialize: the reply carries an Mcp-Session-Id header, and the server's instructions to the agent (below).
  2. notifications/initialized.
  3. tools/call with the session id, as often as needed. A server that forgot the session (it restarted) answers 404, and the client starts a new one.

Responses

run_query and check_query return the same object, as structured content and as JSON text. Fields that don't apply are left out. The result is marked an error when the query was refused, or (for run_query) when the database failed to run it.

FieldWhat it is
refusedWhether a check refused the query. Nothing runs when it did.
profileThe profile the query was checked for.
session_idThe session the request belongs to: this connection. The audit log records it, so sql-warden audit tail --session <session_id> lists everything the session asked. It is sql-warden's own id, derived from the Mcp-Session-Id header rather than being it: that header is what lets a client use the connection, so it stays out of responses and the audit log.
checkThe check that refused it: parse, shape, access, masking, cost, budget or audit.
codeWhy, as a code an agent can act on: see Refusal codes.
reasonWhy, in a sentence, naming the offending table, column or function.
sqlThe SQL that ran, or would run: regenerated from the checked query, comments dropped, rewrites applied.
rewritesHow sql-warden changed the query, e.g. added LIMIT 101 (row cap 100 + 1 to detect truncation).
masked_columnsThe result's columns that come back masked (or would, for a dry run): column, position, strategy (redact, partial, hmac or null) and the sources it comes from, as schema.table.column.
costThe database planner's estimate, from EXPLAIN (never run): total_cost against the profile's max_total_cost, est_rows (rows it expects to return) and top_node, the step that adds the most cost. On an allowed query, and on one the cost check refused.
budgetWhat the session has used of its budget, this request included: queries, total_cost, rows_returned and refusals, each with used and, where the profile sets a limit, limit and remaining; and exhausted, the limit the session has reached, if any. Missing when the profile sets no limits. The budget_status tool returns the same at any time, free.
traceOne step per check that ran, in order: check, passed, code, reason, duration_ms. Checks after a refusal don't run.
resultrun_query only: columns, rows, row_count, truncated (more rows than the row cap; only the first are here) and duration_ms. Exact numbers come as strings, times in ISO 8601.
errorThe database's error, when the query was allowed but failed to run (a timeout, a division by zero).
audit_idThis request's record in the audit log: sql-warden audit show <audit_id>. Missing only when the record couldn't be written, and then the response is an AUDIT_UNAVAILABLE refusal.

list_tables returns {profile, tables} and describe_table returns {profile, table}. Each table has schema, name, the columns the profile may read (name, type, and mask if the column comes back masked) and all_columns, which is true when SELECT * works.

Refusal codes

CodeCheckRefused when
PARSE_ERRORparseThe SQL is empty or doesn't parse.
MULTIPLE_STATEMENTSshapeMore than one statement.
NOT_A_SELECTshapeAnything but a SELECT, UNION or CTE query.
NOT_READ_ONLYshapeA SELECT that writes or locks: a data-modifying CTE, SELECT … INTO, FOR UPDATE/SHARE.
FUNCTION_NOT_ALLOWEDshapeA dangerous built-in (pg_sleep, pg_read_file, dblink, query_to_xml, …), a function in shape.denied_functions, or one that isn't standard SQL and isn't in shape.allowed_functions.
TOO_MANY_JOINSshapeMore joins than shape.max_joins.
SUBQUERY_TOO_DEEPshapeSubqueries or CTEs nested deeper than shape.max_subquery_depth.
LIMIT_REQUIREDshapeNo LIMIT, with shape.limit: require. (With inject, the default, one is added.)
LIMIT_TOO_HIGHshapeA LIMIT above the row cap, with shape.limit: require. (With inject, it is lowered.)
INVALID_LIMITshapeA LIMIT it can't enforce: LIMIT ALL, an expression, FETCH … PERCENT or WITH TIES.
TABLE_NOT_ALLOWEDaccessA table the profile may not read, or one that doesn't exist: the two look the same.
COLUMN_NOT_ALLOWEDaccessA column the profile may not read, in any clause.
STAR_NOT_ALLOWEDaccess* (or a whole-row reference) on a table the profile may read only some columns of. The reason lists them.
CATALOG_UNAVAILABLEaccessThe tables and columns couldn't be read, so access couldn't be checked.
MASKED_COLUMN_IN_PREDICATEmaskingA masked column used to filter, join, group, sort or compare rows (WHERE, JOIN, GROUP BY, ORDER BY, DISTINCT, UNION): what comes back would depend on the values the mask hides. WHERE ssn LIKE '123%' reads an SSN a digit at a time.
MASKED_COLUMN_IN_EXPRESSIONmaskingA masked column inside an expression, such as upper(email), or one that can't be followed to the result. It can only be selected as it is, or counted with COUNT(column).
COST_TOO_HIGHcostThe planner estimates the query costs more than the profile's max_total_cost. The reason gives the estimate, the limit and the costliest step, e.g. Nested Loop for a cross join.
COST_UNAVAILABLEcostThe database couldn't be reached, or took too long to plan the query, so its cost is unknown. Worth retrying later.
PLAN_FAILEDcostThe database rejected the query while planning it, before anything ran: a type error, a table its role can't read, a constant like 1/0. Its error says why; retrying won't help.
BUDGET_EXHAUSTEDbudgetThe session has reached one of its profile's limits: queries run, their total estimated cost, rows returned, or requests refused. Nothing more runs in this session, and no other check looks at the query.
COST_OVER_BUDGETbudgetThe planner estimates the query costs more than the session has left to spend. A cheaper query may still fit.
BUDGET_UNAVAILABLEbudgetWhat the session has used couldn't be read back from the audit log, so its budget couldn't be checked. Nothing runs; worth retrying later.
AUDIT_UNAVAILABLEauditThe request couldn't be recorded in the audit log, so nothing it would return is returned.
INTERNAL_ERRORanyA check crashed. The query is refused rather than let through unchecked.
